Scope: HQ + Franchise flows, current production tenant, plus source inspection of the current repo state.

## Method

- `PASS` = verified live and/or clearly implemented in code.
- `FAIL` = broken live or clearly mismatched vs expected behavior.
- `PARTIAL` = feature exists, but exact expected behavior/data was not fully verified or is thinner than the scenario assumes.
- `BLOCKED` = requires write access on production, third-party OAuth/webhooks, outage simulation, or lab tooling.
- `NOT_IMPLEMENTED` = the current app does not contain the feature in a meaningful form.

## Important context

- I did not mutate production data unless the action was effectively read-only.
- OAuth connect/disconnect, webhook tests, and most save/update flows were treated as blocked on the live tenant.
- A few statuses below come from code inspection rather than live execution. Those are marked explicitly in the note.

## Highest-risk gaps

- Mobile UX is still weak in HQ, especially dashboard, calendar, and annual-plan related layouts.
- `Calendar` and `Annual Plan` are driven by different data sources, so they are not synchronized.
- `Compliance` is currently a campaign reach/activation page, not a policy/compliance page with RUT/ROT and forbidden-word guidance.
- Franchise flow is a download portal, not yet an approve/reject/local-adaptation workflow.
- Settings are much thinner than the scenario set assumes.
- Integrations UI exists, but OAuth/webhook coverage is blocked in prod, and token storage is not secure enough server-side.
